# 五状态循环协议

## 唯一合法循环

```text
越界投射 → 投射结算 → 收集碎片 → 自由追溯历史 → 越界投射
                              └─ 核心碎片全部集齐 → 通关结算
```

每条助手消息只处于一个状态。除“收集碎片”的条件分支外，每个状态只有一个合法后继状态。不得跳过、倒退、在同一回合混合两个状态。

## 1. 越界投射

### 做什么

世界中的一个生命面对局部困境，向玩家投射未经翻译的感受和一个没有标准答案的抉择。展示发送者、原始信号、翻译问题及包含“沉默”的选项。等待玩家回答。

### 流转

玩家给出答案或选择沉默后，只能进入 `投射结算`。

## 2. 投射结算

### 做什么

说明玩家概念被接收者理解成什么、接收者采取了什么局部行动，并记录延迟回响。答案可被误解或拒绝，不直接授予核心碎片，不改变文明历史锚点。

### 流转

结算展示完毕后，只能进入 `收集碎片`。

## 3. 收集碎片

### 做什么

创造者根据刚才的投射、结算及已追溯历史，提出一个具有可判定答案的问题。玩家通过回答证明自己理解了某条因果联系。答对后脚本把对应碎片推进一个阶段；答错时给提示，本状态继续，直到该问题通过。

### 流转

- 当前问题未通过：保持 `收集碎片`，不增加碎片进度。
- 问题通过且仍有核心碎片未集齐：进入 `自由追溯历史`。
- 问题通过且全部核心碎片均为 `connected`：进入 `通关结算`。

这里的“集齐”必须由脚本读取存档判断，模型不得自行宣布。

## 4. 自由追溯历史

### 做什么

玩家自由询问这个世界曾经发生过什么，也可观察、测量或要求推进到某个历史节点。镜机每回合只回答一个调查主题，提供下一轮越界投射所需的背景和线索，但不直接结算下一个镜谕。

### 流转

首次从收集碎片进入本状态时记为第 1 个连续追溯回合：

- 玩家继续追问同一历史支线、主动要求深入或明显保持沉浸时，倾向继续 `自由追溯历史`。
- 玩家没有继续追问、要求返回主线或输入趋向行动时，进入下一轮 `越界投射`。
- 最多允许 3 个连续追溯回合；第 3 个结束后必须进入 `越界投射`，即使玩家仍想深入，也要先完成下一轮主循环。

### 流转

```text
自由追溯历史 → 自由追溯历史  （仅连续计数小于 3 且玩家保持沉浸）
自由追溯历史 → 越界投射      （玩家退出支线，或已完成第 3 次追溯）
```

## 5. 通关结算

### 做什么

这是最终重建世界的自由问答状态。创造者围绕尚未闭合的核心主张追问，玩家可以连续回答、修正和补充。脚本逐项记录已验证主张。

必须验证：

1. 世界位于一颗行星的球形空心地核中。
2. 生命由半导体结构自然演化，依靠放射性与电磁过程生存。
3. 有限空间及掘进碎岩塑造了禁令、政治和地层战争。
4. 密度递减与引力引导文明向外，随后发现液体、气体、浮力，最终抵达海面与星空。

### 流转

- 尚有主张未验证：保持 `通关结算`，继续自由问答。
- 全部主张通过：保持标签 `通关结算`，但把存档 `completed` 设为 `true`，输出最终世界重建、统计和公开故事包选项。

通关后不再接受新的游戏回合；只能执行导出、查看记录或开始新游戏。

## 回合接受规则

Python 状态机读取上一回合、当前存档和候选回合：

- 候选 `meta.label` 必须属于五个合法值。
- 候选回合号必须是上一回合号加一。
- 候选标签必须符合上述迁移。
- 存档中的当前标签必须等于上一回合标签。
- `收集碎片 → 通关结算` 只有在候选状态更新后全部核心碎片均为 `connected` 时允许。
- `收集碎片 → 自由追溯历史` 在碎片未集齐时允许。
- `通关结算` 完成只由全部必要主张验证决定。
- 存档维护 `history_streak`。进入自由追溯时从 1 开始，每次自循环加一；达到配置上限后拒绝再次自循环，进入越界投射时清零。
- 任一验证失败时拒绝候选回合，且不得改写存档或回合历史。

## 固定进度

每个候选回合必须包含且只能包含：

```json
"progress": {
  "projection_count": 1,
  "fragment_count": 0
}
```

- `projection_count`：本局已接受的越界投射次数；每次进入新的越界投射时由状态机加一。
- `fragment_count`：状态为 `connected` 的核心碎片数量。

两项都由 Python 根据存档计算。模型不得自行修改，不显示碎片总数，也不得增加其他进度字段。
